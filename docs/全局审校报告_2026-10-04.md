## 二、数据丢失 / 物品复制（最优先）

### D1 ✔ P2 倒地时若开着任何菜单，背包被清空 — CRITICAL
- **位置**：`Patches\Patches.DeathRespawn.DownedState.cs:24-26` → `Main.P2Backpack.cs:350-370`（`ForceResetP2Backpack`）→ `Runtime\P2InventoryStore.cs:121-145`（`Reset`）
- **机制**：`ForceResetP2Backpack` 先 `CloseP2Backpack()`（把视图存进 `_p2Slots`），随后调 `P2InventoryStore.Reset()`，而 `Reset()` 末尾无条件 `_p2Slots = null`（第 144 行）。下次开背包 `RestoreBackpack(view, null)` 把所有格子 `SetItem(null)`，再存档就落盘。
- **触发**：P2 在背包、研究台、储物箱、交易站、鱼饵菜单等任一菜单打开时被击倒，或被 P1 背起。手持栏不受影响，所以不是设计上的死亡掉落。
- **根因**：`Reset()` 被"离开世界清内存"和"倒地时放弃 swap"两种语义共用。
- **修法**：拆成两个函数；`_p2Slots = null` 只留给 `Main.ResetForWorldLeave`。

### D2 ✔ P2 装备跨世界泄漏并复制 — HIGH
- **位置**：`Runtime\P2EquipmentStore.cs:22,84`；`Runtime\P2SaveStore.cs:159`；`Main.cs:310-353`
- **机制**：`_equipped` 是纯托管静态字典，`ResetUnityStatics` 不清它；`P2EquipmentStore.Clear()` 全库零调用；`ResetForFreshWorld` 只在目标世界**没有** P2 存档时才跑；`ResetForWorldLeave` 不碰装备。
- **后果**：世界 A 里装备的背包/滑索工具带进世界 B，白拿额外背包格，下次存档写进 B，等于复制。
- **修法**：`ResetForWorldLeave` 里调 `Clear()`；`LoadAndRestoreP2` 应用存档前先清。

### D3 ✔ P2 存档写入非原子，读档失败会导致覆盖丢档 — HIGH
- **位置**：`Runtime\P2SaveStore.cs:134`（`File.WriteAllText` 直接覆盖）、`:168-198`（逐行 `int.Parse` 无保护）、`:208-212`
- **机制**：写到一半崩溃/断电会留下截断文件。读档时任何一行解析失败，整份放弃并返回 false，P2 以空背包开局，下一次 `SaveP2` 把原文件覆盖。
- **修法**：写 `.tmp` 再 `File.Replace` 并保留 `.bak`；逐行 `TryParse`，坏行跳过；解析失败时把原文件改名为 `.corrupt` 而不是让它被覆盖。

### D4 ○ P2 背包打开期间存档，存的是旧快照 — HIGH
- **位置**：`Runtime\P2InventoryStore.cs:37-45`（`GetP2BackpackSnapshot` 只在 `_swapped` 时读视图）
- **后果**：P2 开着背包时 P1 存盘，背包↔手持栏之间的移动、丢弃、光标上拿着的物品都不在快照里，读档后表现为复制或丢失。
- **修法**：背包视图打开时直接对视图取快照，并把 `_p2Held` 合并进去。

### D5 ✔ 拆除被占用的箱子可无限刷物品 — MEDIUM
- **位置**：`Patches\Patches.P2Build.cs:592-609`
- **机制**：Prefix 无条件 `AddItem` + `ReturnItemsFromBlock(giveItems: true)`；原版 `RemovePlaceables.cs:139-146` 是先用 `giveItems:false` 判定能否拆除，通过才拆。箱子被 P1 打开时原版拒绝拆除，但 P2 已经拿到物品。
- **修法**：先用 `giveItems:false` 判定。

### D6 ○ 背包操作里的几处丢失/复制路径 — MEDIUM
- `Main.P2Backpack.cs:758-774`：`TrySetP2HeldOrigin` 回填来源槽时不检查是否已被占用，会覆盖掉拿起期间放进去的物品。
- `Main.P2Backpack.cs:318-324`：关背包时手上物品只尝试放进第一个空背包格，背包满就直接丢弃。
- `Main.P2Backpack.cs:1003-1061`：对装备槽按 Y（快速移动）或 LT+Y（丢弃）没有走 `ClickEquipSlot` 的分流，装备 store 不更新（复制），且 `Slot_Equip.SetItem` 会动到 P1 的 `PlayerEquipment`。
- `Main.P2Backpack.cs:900-905,938-962`：快速移动不检查 `Slot.active`，物品会落进未激活的隐藏背包格。

## 三、已知未解问题的线索：P1 死后尸体"满天乱飞"

### B1 ✔ mod 与原版死亡分支每帧抢写 parent — HIGH（机制已对照原版确认，未实机复现）
- **位置**：`Patches\Patches.DeathRespawn.DownedState.cs:125-133,154-178`；原版 `SourceCode\PersonController.cs:529-577`
- **原版**：本地玩家死亡后，每帧向下打 1 m 射线。没打到木筏地面（水里、岛上、空中）就 `transform.SetParent(null)`，世界坐标保持。
- **mod**：同一帧 `p1.transform.SetParent(P1DownedAnchorParent, false)`（**`worldPositionStays=false`**，第 171 行），再强写 `localPosition`（第 174 行）。
- **后果**：`SetParent(x, false)` 保持的是 local 值，上一帧的世界旋转被当成 local 旋转，再乘一次父节点（`lockedPivot`，随浮力倾斜）的旋转。两边每帧交替，旋转逐帧累积。这与"环境特定"的表现吻合：只有 P1 死在木筏地面之外时原版才会走 `SetParent(null)` 分支。
- **另外两点**：
  - `GetP1DownedRaftParent` 优先取 **P2 当前的 parent** 而不是木筏（第 127 行）。P2 坐在雪橇车上时，P1 的尸体会被挂到车上。
  - `TickP1DownedStabilize` 每帧被调两次（`MenuGate.cs:14`、`P1DownedCamera.cs:31`）。
- **修法方向**：不要每帧钉 parent/位置，只镜像原版规则；必须锚定时用 `worldPositionStays=true`，parent 只允许 `lockedPivot`。master 上未提交的 `[P1DownDiag]` 日志正好能验证这个机制（看 `par=` 是否在 `null` 与锚点之间逐帧翻转）。

## 五、状态泄漏与卡死

### S1 ✔ scope 构造函数不具备异常安全，且没有帧边界自愈 — HIGH（概率低，后果重）
- **位置**：`Runtime\P2OriginalScope.cs:62-120`；`Runtime\P2InteractionContext.cs:49-76`；`Main.Tick.cs:29`
- **机制**：构造函数先改全局状态（`PlayerContext.Active = P2`、P2 强制 `isLocalPlayer = true`、换 CM 三件套、压 `isBusy`、`isProcessingP2Ray = true`），后续步骤若抛异常，对象没有返回，`using` 和 Harmony Finalizer 都无从释放。
- **为什么不会自愈**：`MaintainLocalPlayerCM` 在 `PlayerContext.Active != null` 时直接早退；全库只有离开世界时才 `PlayerContext.Clear()` 和 `P2Mode = None`。一旦泄漏，P1 的输入、菜单、背包会以 P2 身份运行到退出世界。
- **修法**：构造函数体包 try/catch，失败时逆序回滚；在 `Main.OnUpdate` 帧首加一个看门狗——若 `PlayerContext.Active != null` 或 `P2Mode != None`，记日志并强制复位。

### S2 ○ 改了全局状态却没有 Finalizer / finally
- `Patches\Patches.DeathRespawn.Harmony.cs:73-157`：`StartCarry` 的 Prefix 把 carrier 的 `IsLocalPlayer` 置 false，只在 Postfix 还原。原版抛异常时 P1 永久变成非本地。
- `Main.P2AnimalCarry.cs:244-256`：`Container.localPlayer` 的还原写在 `using` 之外且无 finally。
- `Patches\Patches.P2Combat.cs:483`：`Throw` 的 scope 创建顺序与另外三处相反（先 Ctx 后 Busy），释放时会把 P1 的 `IsBusy` 写成 false。
- 制作/研究/交易克隆时对 `ComponentManager<T>.Value` 的还原是手写的，没有 try/finally（`Main.P2Crafting.cs:197-210`、`Main.P2Research.cs:138-144`、`Main.P2TradingPost.cs:161-170`）；背包那边用的是异常安全的 `PreserveCurrentSingleton()`，写法不统一。

### S3 ○ P2 的"附着/死亡/复活"状态没有统一的强制退出入口
同一个根因下的几个表现：
- `Patches\Patches.DeathRespawn.P2Respawn.cs:98-129`：P2 复活后在床上等起床时床被拆，`waitingForRespawn` 永久为 true → P2 永久无敌、饥渴/生命冻结。
- 原版在 P2 非本地时跳过 `IsLocalPlayer` 门控的清理分支：P2 坐着/在雪橇车上死亡后 `PlayerNetworkManager.IsAttached` 残留为 true → 复活后不能蹲、TP 下身体不随视角转。
- `Main.P2AnimalCarry.cs:40-50`：P2 搬着动物/桶被击倒不会放下；举着望远镜被击倒时遮罩和放大的 FOV 留在倒地画面上；LT 建造菜单同理。
- `Patches.DeathRespawn.P2Respawn.cs:11,18,300-337`：`SplitScreenDeathFlow` 的静态量不随离开世界重置，协程宿主销毁后 `P2PostBedExitRestoreRoutine` 永远非 null，下一局 P2 的手部相机被关、FP 手臂被隐藏。
- **修法方向**：提供一个"P2 强制退出所有附着态"的函数（在 `P2OriginalScope` 内调用原版的 stop），死亡、离开世界、对象销毁三条路径统一走它；给 `SplitScreenDeathFlow` 加 `ResetForWorldLeave()`。

### S4 ✔ `_p2Fwcs` 缓存永不重置 — MEDIUM
- **位置**：`Main.P2FillWater.cs:23,40-50`
- 字典只在为 null 时建一次，`ResetForWorldLeave` 没清它。进入第二个世界后里面全是已销毁的组件，P2 无法装水，直到重启游戏。热重载时 `ResetUnityStatics` 会把它 `Clear()` 成"空但非 null"，同样不会重建。

### S5 ○ 菜单状态机缺口
- `Runtime\P2UnstuckMenu.cs:28-68`：暂停菜单的 `Open` 不检查其他菜单是否开着，`Close` 无条件恢复 gameplay；背包开着时按 Start 再关掉，P2 可以带着打开的背包走动。
- `Runtime\UiRouter.cs:144-152`：`OpenStorage` 先置 `IsUsingMenu = true`、`CurrentStorage`，再调可能静默失败的 `Main.OpenP2Storage`。
- `Runtime\InputRouter.cs:296-340`：手柄 60 帧巡检的排除条件不含 Unstuck 菜单，最多 1 秒后重新启用移动/开火。
- `Patches\Patches.P2Zipline.cs:126-137`：滑索按 B 脱离没有接 `SuppressP2CrouchOnExit`，落地即蹲。
- `Main.P2Research.cs:72-77`：P2 开研究台不设置原版的占用标记，P1 可以同时打开同一台。

### S6 ✔ 一个子系统抛异常会拖垮整帧的 P2 tick
- **位置**：`Runtime\SplitScreenRuntime.cs:80-126`
- `Tick` 里十几个 `Tick*` 顺序调用，没有任何隔离。任何一个抛异常，后面的都不执行，且每帧重复抛。建议每个子系统单独 try/catch 加节流日志。

### S7 ○ 没有联机会话门控
- **位置**：`Main.Spawn.cs:131-150`（`GetSplitSpawnBlockReason`）
- F9 在任何世界都能生成 P2，不检查是否有真实远端玩家、是否为主机。P2 以伪 ID 999 绕过 `Message_Player_Create` 广播加入，之后的采集/建造消息会带着远端不认识的 P2 对象发出去。建议拒绝 `remoteUsers.Count > 1` 或非主机的会话，或明确写明"仅限单机"。

## 七、Harmony 稳健性与代码卫生

- **Transpiler 全部"找不到就放行"** ○：11 个 Transpiler 没有一个统计匹配次数或记日志（`Patches.Rendering.cs:202-224`、`Patches.Input.cs:97-108`、`Patches.P2Hook.cs:67-79,249-261`、`Patches.P2Consume.cs:20-30`、`Patches.P2Zipline.cs:111-120,578-591`、`Patches.P2Snowmobile.cs:157-207`）。游戏更新后会静默退化成读 P1 输入。
- **`PatchAll` 没有 try/catch** ✔（`Main.cs:170`）：多个 `TargetMethod()` 里的 `AccessTools.Method` 结果不判空，任一目标方法消失会让 `PatchAll` 半途抛出，留下半打补丁的状态。
- **同一方法被多个文件叠加补丁，顺序是隐式的** ○：`CustomInputConfig.IsPressed / WasPressedThisFrame / WasReleasedThisFrame` 在 `Patches.Input.cs`、`Patches.P2Build.cs`、`Patches.P2Zipline.cs` 各有 Prefix，没有 `[HarmonyPriority]`，正确性依赖 csproj 的 Compile 顺序。
- **重复补丁** ○：`Helper.LocalPlayerIsWithinDistance` 被打了两遍（`Patches.Interaction.cs:362-371` 是 `Patches.P2DeviceFallback.cs:24-33` 的超集）；`Patches.DeathRespawn.Harmony.cs:159-196` 两个 `StopCarryingPlayer` Prefix 逐字重复。
- **遗留诊断** ○：`Patches\Patches.P1RaycastDiagnostics.cs` 生产环境常驻（只读，可整体删除）；`Main.P2AnimalCarry.cs:175-207` 的 `DumpCarryDiag` 自称"查完删除"仍在执行；`Patches\Patches.RadioCoroutineDiag.cs` 名为诊断实为会改状态的修复，应改名。
- **死代码** ○：`Main.P2UI.cs`（空类）、`Patches.P2BackpackGuard.cs`（Prefix 恒返回 true）、`Main.cs:209` 空方法 `PatchCMGetters` 仍被调用、`Main.P1Ui.cs:78-111` 的 `SetGameCanvasOverlay`、`InputRouter` 的 `EnterP2MenuCursorMode` 等、`DeathRespawn` 里 `CompleteP2BedReviveAfterDelay` 等三个无调用方的函数。

## 九、建议的处理顺序

1. **先收拾仓库**（R1–R3）：把分支合进 master（零分叉，可直接快进），`git worktree prune`，处理 master 上的未提交改动。否则后面的修复都会落在旧代码上。
2. **数据安全**：D1（倒地清包）、D2（装备跨世界）、D3（存档原子性与坏档保护）、D4（开包存档）。这几条改动都小，收益最大。
3. **P1 倒地乱飞**（B1）：机制已经很具体，重装 Raft 后用现成的 `[P1DownDiag]` 日志一次就能证实或证伪。
4. **P1 纯净度**（第四节）：先确认 `BackpackFirst` 和 `SmelterRecycle` 是否有意，再决定加门控还是删除；P3（VSync 写盘）建议必修。
5. **兜底机制**：S1 的帧首看门狗、S6 的子系统隔离、S3 的"强制退出所有附着态"入口。这三项是结构性的，能一次性消掉一类问题。
6. **性能**：F1、F2、F3 三条是每帧全场景扫描或整包换入换出，优先；其余可择机。
7. **卫生**：Transpiler 加匹配计数与日志、`PatchAll` 包 try/catch、删死代码和遗留诊断、更新 `CLAUDE.md` / 验收表 / `sync-to-rml.ps1`、统一版本号和许可证、从 `72b30d35` 之前的历史找回被清空的注释。
